## 2. プロダクト全体像（仕様統合）
### 2.1 ゲームコンセプトとループ
- コンセプト: くそざこでも立ち回りと再挑戦で打開する群衆戦術ゲーム。
- 基本ループ: `戦闘` ↔ `キャンプ`（拠点強化/訓練/作戦/ショップ）。
- 体験版ステージ目標:
  - 勝利: `ドラゴン撃破` かつ `敵拠点3か所封鎖`（順不同、片達成では継続）。
  - 敗北: `味方拠点全滅` かつ `ユウナ戦闘不能`。
- 1ラン目安: フルクリアで 12〜18 分。5〜10 分帯は内部検証用の短縮構成としてのみ扱う。

### 2.2 本格実装フェーズで固定する方針
- まず守るべき体験は「弱い群れを、プレイヤーの立ち回りと判断で勝たせる」こと。プレイヤー単騎の無双感は主目的にしない。
- コアループは `キャンプで育てる` → `戦闘で封鎖を進める` → `敗北/勝利後に次の強化判断をする` の反復で固定する。
- ラン中の主な成長は「操作理解」「ちび制御」「封鎖順の判断」に寄せ、恒久成長だけで押し切る構造にはしない。
- 本フェーズの正本入力は `WASD + Space + J/K/L/I/Q` を採用する。旧MVPキーは移行完了までの互換入力であり、UI/チュートリアルの正本には使わない。
- 戦闘中リスポーンは原則なしで進める。再出撃要素は拠点生産とラン間成長に集約する。

### 2.3 対応環境・技術前提
- C++17
- SDL2 / SDL2_image / SDL2_ttf
- CMake 3.24+
- 解像度1280x720固定
- フォント: `assets/ui/NotoSansJP-Regular.ttf`
- 実行入口: `src/main.cpp` -> `GameApplication`

### 2.4 シーン遷移と実行フロー
- `SceneStack`で遷移管理。
- 起動時は`TitleScene -> BattleScene -> CampScene`導線（現行運用）。
- キャンプ終了で`BattleScene::startRunFromCamp`。
- バトルは固定ステップ積分（既定`1/60`）で`WorldState::step`を実行。

## 3. エンティティ・戦闘・入力の統合仕様
### 3.1 ユニット構成
- ユウナ（プレイヤー）:
  - 直接操作、近接軸、ガード、号令、火球など。
  - 現行実装の代表値（system_overview基準）: HP60, DPS15, 速度3.2u/s。
- ちびわふ:
  - 個体属性: 名前/称号/職業/性格。
  - 保存上限100、戦場上限は200運用。
  - 生成Lvは幾何分布+訓練所による平均上げ。
- ネームド:
  - ミリー/マリー/ココ。後衛傾向、危険回避、各1スキルの最小構成。
- 敵:
  - スライム、ゴブリン、マジシャン、バット、トリトリ、ゴーレム、ドラゴン。

### 3.2 プレイヤー入力（正本）
- 移動: `WASD`
- ダッシュ: `Space`
- `J`: 主魔法 `fire_ball`
- `K`: ガード
- `L`: 号令 / 防衛集合
- `I`: 回復パルス
- `Q`: リング操作 / ちび挙動制御
- デバッグ/補助: `F8`速度、`F9`リロード/表示切替、`F10`デバッグ
- 矢印、`F1-F4`、`Z/X`、`U`、右クリック発動などの旧MVP入力は移行期間の互換扱いであり、本仕様の正本入力ではない。

### 3.3 号令・陣形・スキル
- 号令:
  - `L` で防衛/集合系の号令を出す最小入力セットを正本とする。
  - 追加の号令バリエーションは HUD/入力負荷を見て段階導入する。旧MVPの4種号令は参考案として扱う。
- 陣形:
  - 初期実装は `Q` によるリング制御を優先する。
  - Swarm/Wedge/Line/Ring の固定プリセットは拡張候補として保持し、導入時は整列ペナルティ込みで再評価する。
- スキル:
  - 本フェーズのユウナ基本セットは `fire_ball` / `guard` / `orders` / `heal_pulse` / `ring_control`。
  - 体験版v1.1確定差分: ユウナの主魔法は`fire_ball`（Dmg4/CD2.4/MP10/速度160）。
  - `Rally` / `Wall` / `Surge` / `Self Destruct` など旧MVPスキルは再採用する場合のみ別途仕様復帰させる。

### 3.4 ガード仕様（体験版v1.1確定差分）
- K長押しでガード、移動不可。
- 前方160度の被弾を0化（近接/飛び道具/扇形）、床DoTは軽減なし。
- MPコスト:
  - 秒間消費は廃止。
  - ヒット毎に`1 + ceil(防いだダメージ*0.20)`。
  - 連続ヒットは0.2s窓で合算。
- パーフェクトガード:
  - 0.18s内成立で固定1MP免除+総コスト0.5倍。
  - 雑魚のみ0.2sひるみ。
- MP0被弾でガードブレイク（0.6sスタン+2.0s再ガード不可）。

## 4. AI・性格・士気の統合仕様
### 4.1 ちびAIの基本
- 0.5秒tickで行動スコア評価。
- 行動7種（突撃/敵拠点/逃走/ユウナ追従/味方追従/拠点防衛/うろうろ）。
- Panic中は基本攻撃禁止。
- 直前行動ヒステリシス（+20%）でブレ抑制。

### 4.2 性格二軸
- 軸:
  - ゆうかん（びびり〜ちょとつ）
  - ちせい（おばか〜かんがえるこ）
- 代表効果:
  - Panic閾値: 0.60 -> 0.15
  - 再ターゲット遅延: 0.8s -> 1.8s
  - AoE回避倍率: 0.85 -> 1.30

### 4.3 Panic分岐（体験版v1.1）
- 分岐4系統:
  - とっこう
  - かいてん（拠点退避）
  - すがる（ユウナ背面貼り付き）
  - にげまどう
- 強制Panic（ユウナダウン時）:
  - ちびは攻撃禁止。
  - とっこう無効。
  - すがるはかいてんへフォールバック。

### 4.4 敵AIの要点
- ゴブリンはPanicタグ対象を優先（bonus +0.30）。
- トリトリは拠点狙い比重が高い。
- ボスは専用行動（ゴーレム耐久戦、ドラゴン扇形炎）。

### 4.5 群れ味付け
- 軽量Boids:
  - Cohesion 半径96px
  - Separation 18px
- 性格に応じて散開/回避を変化。

## 5. ステージ・スポーン・勝敗の統合仕様
### 5.1 ステージ1の進行
- 基本: 敵拠点3箇所を中心にループ進行。
- 封鎖と時間条件で中ボス/最終ボスを段階解放。
- ドラゴン撃破先行でも、未封鎖拠点が残ると継続。

### 5.2 スポーン方針（体験版v1.1）
- 非ボスは拠点封鎖まで継続湧き。
- 味方湧き > 敵湧き（初期設計意図）。
- 代表値:
  - 味方: 1.00体/s/拠点（強化で上振れ）
  - 敵拠点: 0.10 -> 0.18体/s
  - 上限: 敵40、ちび200（仕様v1.1案）
- 拠点封鎖で該当拠点の湧き即停止、視覚演出のみ残す。

### 5.3 拠点オーラ
- 半径128px
- 与ダメ1.05倍
- 被ダメ0.90倍
- 毎秒+1HP
- 重複は最大値のみ（非スタック）

### 5.4 ミッションモード（MVP拡張）
- Boss / Capture / SurvivalをObjectiveSystemで統一判定。
- `assets/data/world/mission_levelX.json`を読んで勝敗判定。
- 既存ウェーブ脚本と併用可能。

## 6. 経済・キャンプ・周回の統合仕様
### 6.1 経済
- 入手: 敵撃破、ミニ実績、エリート追加報酬など。
- 使用: 拠点強化、訓練、作戦、メタショップ。
- 目安: 1周ごと15-25%の成長感を設計指標。

### 6.2 キャンプ4タブ
- 拠点強化: HP/防御/生成速度/オーラ再生
- 訓練所: ちび生成Lv平均μ引き上げ
- 作戦: ネームドのプリセット選択（後衛固定等）
- ルーの店: 恒久バフ+消費型トークン

### 6.3 `mana_gain_token`と`mana_cap`
- `mana_gain_token`:
  - 1個5マナ
  - 次ラン開始時に1個自動消費
  - そのランの獲得マナ+10%
- `mana_cap_up_s`:
  - ラン中の所持上限を恒久拡張

### 6.4 リザルトと持ち越し
- リザルト到達時に自動で口座へ振替・自動セーブ。
- 持ち越し:
  - 強化、ショップ進行、訓練μ、作戦、マナ口座
- リセット:
  - マップ状態、封鎖フラグ、スポーン状態、ラン統計

## 10. ゲーム内エディタ要件（v1.0統合）
### 10.1 目的
- JSON手編集依存を減らし、GUIで編集→即検証のループを成立させる。
- Steam向けには安全に無効化できる構造（`EDITOR_BUILD`等）。

### 10.2 v1スコープ
- 含む:
  - ステージ/ウェーブ/拠点/Hazard編集
  - ユニット/ジョブ編集
  - AI/性格編集
  - ギミック床編集
  - デバッグプレイ連携
  - Undo/Redo、保存、オートセーブ
  - 敵拠点ごとの構成率編集
- 後回し:
  - キャンプ/メタ詳細
  - ユーザー配布連携
  - 本格自動プレイ統計

### 10.3 機能要件（F-1〜F-8）
- F-1 Stage Editor:
  - TMXオーバーレイ、拠点/ゲート/Hazard編集、タイムライン編集
- F-2 ギミック編集:
  - 通行/効果タイル、effect定義編集、ヒートマップ可視化
- F-3 Unit/Job Editor:
  - 基礎ステ、ジョブパラメータ、戦闘力目安表示
- F-4 AI/Personality Editor:
  - 2軸グリッド、morale、行動スコア、気質プリセット編集
- F-5 敵構成エディタ:
  - 拠点単位の出現率%編集、100%自動整形、プリセット
- F-6 Debug Play連携:
  - エディタから即Battle起動、（将来）時間ジャンプ/固定シード
- F-7 Undo/Redoと保存:
  - 編集単位定義、`Ctrl+S`、autosave復旧導線
- F-8 実践補助:
  - スナップショット、タグメモ、難易度バー、テストログ

### 10.4 非機能要件（N-1〜N-5）
- N-1 ビルド分離:
  - リリース混入防止、多段起動条件
- N-2 データ管理:
  - `assets/core|stages|dev|dev/logs`分離
  - 保存前バリデーションと破損復旧
- N-3 パフォーマンス:
  - 80x45 + UIでも操作快適
- N-4 スキーマ耐性:
  - バージョン管理/移行スクリプト/共有スキーマ
- N-5 再現性:
  - シード・起動条件ログ

### 10.5 実装フェーズ案
1. Phase 1: 最低限編集+デバッグ起動
2. Phase 1.5: Undo/Redo、敵構成、Unit/Job v1
3. Phase 2: AI編集、難易度メーター、スナップ、バリデーション

## 12. 要件再定義のための意思決定テンプレート
### 12.1 先に固定する項目（Must）
- コアループ: 1ランの開始〜終了定義
- 勝敗条件: 単一条件か複合条件か
- 1ラン時間帯: 目標レンジ
- 入力標準: 戦闘キーとキャンプキーの正本
- ラン中リスポーン方針: 有/無/限定

### 12.2 システム判断（Should）
- 号令と性格AIの優先度
- ボス導線（時間/封鎖進行/混合トリガ）
- 経済成長率（runごとの伸び）
- Tipsの算出指標（Panic比率等）

### 12.3 後回し（Nice）

## 13. 再要件定義時のチェックリスト
- 仕様正本の競合がない（Active重複なし）
- 数値正本をJSONに寄せた
- 入力仕様が文書間で矛盾していない
- 勝敗条件がコード/データ/文書で一致
- 保存/持ち越し/リセット範囲が明文化された
- テレメトリとQA受け入れ条件がセットである
- 未確定事項に期限と担当がある
