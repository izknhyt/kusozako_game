# ゲーム内エディタ要件定義 v1.0

## 1. 概要

本ドキュメントは、本作向け「ゲーム内エディタ（自作ツクール）」の要件定義をまとめたもの。

目的は以下の通り。

- ステージ構成・敵/味方パラメータ・AI を **GUI から編集して即テストプレイできる環境** を作る。
- JSON 手編集から卒業し、**バランス調整とステージ量産のサイクルを高速化**する。
- 将来 Steam 配布時にも問題が起きないよう、**エディタ機能を安全に外せる/隠せる構造**を前提に設計する。

---

## 2. ゴール / コンセプト

- 「RPGツクール」的に、  
  **ステージ・敵拠点・ユニット・AI をまとめて編集できる専用エディタ** をゲーム内に持つ。
- 編集した内容を、**ワンクリックでデバッグプレイ / シミュレーション**して確認できる。
- 将来的にステージ量産・難易度調整・他機種展開などに耐えられる、**実践的な“本物のゲームエディタ”寄りの機能セット**を目指す。

---

## 3. スコープ（v1 で扱う範囲）

### 3.1 対象に含める

1. **ステージ編集**
   - マップ / 拠点 / Hazard / ウェーブ / テレメトリ

2. **キャラ編集**
   - `entities.json`（味方・敵ユニットの基礎ステ）
   - `jobs.json`（ちび職のパラメータ）

3. **AI・性格編集**
   - `chibi_personality.json` / `morale.json`
   - `ai_params.json` / `ai_temperaments.json`

4. **マップギミック**
   - 通行不可・通行コスト地形
   - バフ/デバフ・毒床・ダメージ床・強制移動床 などの効果タイル

5. **デバッグプレイ / シミュレーション連携**
   - エディタから **即バトル起動**（必要なら特定ウェーブから）

6. **編集操作まわり**
   - Undo / Redo
   - 保存・オートセーブ
   - 敵拠点ごとの敵構成（出現率％）編集

7. **実践的な補助機能（優先度中）**
   - スナップショット（ステージ状態のスロット保存）
   - プリセット/テンプレ（ウェーブ構成・敵構成）
   - タグ/メモ（TODO 管理）
   - 簡易難易度メーター
   - 自動バリデーション（保存前チェック）

### 3.2 v1 では後回し（将来対応）

- キャンプ / ショップ / メタ進行（値段設定、解禁ステージなど）
- ユーザー向けステージ配布・Workshop 連携
- 自動プレイシミュレーション（統計出しまでやる本格モード）
- ステージ全体一覧＋キャンペーン構成ツール（高機能版）

## 4. 利用者 / 利用シーン

### 4.1 利用者

- ゲームデザイナー / 実装担当（現状は本人）
- 将来的にはレベルデザイナー・プランナーも想定

### 4.2 主な利用シーン

- 新規ステージの作成
- 既存ステージの難易度調整
- 敵/味方/AI パラメータの試行錯誤
- マップギミックの配置と調整

## 5. 機能要件

### F-1. ステージエディタ（Stage Editor）

**目的:** ステージの「戦場の形」と「ウェーブ構成」を GUI で編集可能にする。

- ステージデータのロード / 保存
  - `stage*_config.json`, `spawn_*.json`, `map_defs.json` を対象とする。
- マップビュー
  - TMX を読み込み、グリッド表示（例: 80×45、16px タイル）。
  - 以下をマップ上にオーバーレイ表示：
    - 味方拠点 / 敵拠点
    - ゲート位置
    - Hazard 円
  - オブジェクトはクリックで選択・ドラッグで位置変更可能。
  - グリッドスナップ / 整列ツール、矩形・連続ドラッグによる配置支援。
- 拠点編集
  - 味方拠点：
    - 位置 / HP / オーラ半径 / sealed フラグ 等。
  - 敵拠点：
    - 位置 / HP / 半径
    - スポーンレート（`rate_per_s`, `rate_max`）
    - 敵構成（後述 F-5 で詳細）
- Hazard 編集
  - 位置 / 半径 / 有効・無効 / トリガー条件 等を編集可能。
- グローバル設定
  - `global_caps`（敵・ちび同時出現数など）
  - 味方工場レート (`allyFactory.rate_per_s` など) の編集。
- ウェーブ編集（spawn）
  - 時間軸（`t` 秒）に沿ったタイムラインビュー。
  - `waves` の追加 / 削除 / `t` の移動。
  - 各 wave の `sets`（`gate` / `count` / `interval_s` など）編集。
- タイムライン操作・フィルタ
  - ズーム / パン、特定ゲート・タグ・時間帯だけを表示するフィルタ。
- テレメトリ編集
  - 時間ごとのメッセージやイベントをリスト表示・編集。

---

### F-2. マップギミック・地形エディタ

**目的:** 通行不可・バフ/デバフ床など「地形ギミック」を GUI で配置できるようにする。

- 通行レイヤ編集
  - 通行可 / 通行不可 / コスト高 などをブラシ塗りで設定。
  - TMX レイヤ＋`map_defs.json` の `collision` 設定を利用/拡張。
- 効果レイヤ編集
  - 毒床 / ダメージ床 / バフ床 / デバフ床 / 強制移動床 などをタイルに配置。
  - 各タイルは `effect_id` を持ち、実際の挙動は別 JSON 定義に委ねる。
- レイヤ表示・ブラシ
  - 通行/効果/デバッグオーバーレイの表示切替、矩形・線ブラシ・連続ドラッグ塗りなどの操作補助。
- 効果可視化
  - Hazard / 効果床のダメージ・バフ強度をヒートマップでプレビュー。
- 効果定義（例: `effect_defs.json`）
  - `effect_id` ごとに以下のようなパラメータを持つ：
    - 種類（`DOT` / `INSTANT_ON_ENTER` / `MODIFIER` / `FORCE` 等）
    - ダメージ量 / tick 間隔
    - 移動速度倍率
    - 強制移動方向 / 強さ など
  - エディタから数値・種別を編集可能にする。

---

### F-3. ユニット & ジョブエディタ（Unit / Job Editor）

**目的:** 味方ちび・敵・ボスの基礎ステ＆ジョブ性能を調整しやすくする。

- ユニット一覧
  - `entities.json` に定義されたユニット一覧を表示。
- 基礎ステ編集
  - HP / DPS / 移動速度 / 射程 / 当たり判定半径 / traits などを編集。
- 派生ステ・指標表示
  - ユニットごとの「推定戦闘力スコア」「コスト」をエディタ側で計算し、バーで表示。
  - ステージ難易度ビュー（後述）と連携可能な形を想定。
- ジョブ編集
  - `jobs.json` に基づき、各ジョブの以下を編集：
    - 使用スキル名（将来的に `skills.json` と連動）
    - クールダウン
    - 各種倍率・範囲・デバフ量 等のジョブ固有パラメータ。
- （Nice to have）ジョブプリセット
  - 「タンク寄り」「DPS 寄り」などプリセットの保存・適用。

---

### F-4. AI & 性格エディタ（AI / Personality Editor）

**目的:** ちびの「性格」「士気」「行動優先度」を視覚的に調整可能にする。

- 性格グリッド（`chibi_personality`）
  - ゆうかん / ちせい の 2D グリッド表示。
  - グリッドごとに tokou / cling / kaiten / runaround 等の発動条件・フラグを編集。
- 士気（`morale`）編集
  - `panic` / `mesomeso` / `recovering` / `shielded` など状態ごとに：
    - 移動速度 / 攻撃間隔倍率 / 精度 / 防御
    - オーダー無視率 / 退却挙動 などを編集。
- 行動スコア（`ai_params`）編集
  - `assault` / `flee` / `follow` / `defend` / `wander` など行動ごとの：
    - 基本スコア
    - 距離依存パラメータ
    - ゆうかん / ちせい重み
  を編集。
- 気質プリセット（`ai_temperaments`）
  - 「ちょとつもうしん」「あまえんぼ」「ひきこもり」「なきむし」など：
    - 行動テンプレ
    - 出現比率（spawn_rate）
    - 追加パラメータ（home 距離、回避距離など）をカード形式で編集。
- 気質プリセット比較 / コピー
  - プリセットカードを横並び比較し、差分を見ながらコピー/上書き。
- 性格グリッドのデバッグプレビュー
  - 選択セルの行動スコア棒グラフや発火率を即時表示。
- （Nice to have）簡易 AI テスト
  - 仮想ちびを 1〜数体出して、  
    現在のパラメータでどの行動が発火しやすいかをバー表示し、結果をエディタ上で簡易ログ化。

---

### F-5. 敵拠点ごとの敵構成（出現率）エディタ

**目的:** 各敵拠点から湧く敵の種類・出現比率を GUI で直感的に調整できるようにする。

- 対象: `StageEnemyBaseConfig.weights`（enemy_id → weight）
- 機能：
  - 敵拠点を選択時、「敵構成」パネルを表示。
  - 各敵について：
    - ON/OFF チェックボックスで「この敵を含めるか」選択。
    - 出現率をパーセンテージ（0〜100％）で編集。
  - UI 上は常に合計 100％になるよう自動リスケール。
- 内部保存形式：
  - 現行 `weights` 仕様に合わせ、重み値として保存（% = weight でも可）。
- （Nice to have）補助機能：
  - 構成プリセット（「雑魚多め」「飛行多め」「エリート混ぜ」等）の保存/適用。
  - 各拠点の敵構成から「期待 HP / DPS / 移動タイプ比率」を算出して強さバー表示。
  - 他拠点への構成コピー機能。

---

### F-6. デバッグプレイ & シミュレーション連携

**目的:** エディタで編集したステージを、その場で素早く検証できるようにする。

- デバッグプレイ起動
  - エディタ画面に **「▶ デバッグプレイ」ボタン**を配置。
  - 押下時：
    1. 現在の編集状態（Stage / Spawn / Map / Entities / AI 等）を一時 JSON に保存。
    2. その設定を用いて `BattleScene` を起動。
    3. デバッグプレイ終了後、`SceneStack::pop()` 等でエディタに戻る。
- タイムラインからの起動
  - ウェーブタイムライン上で右クリック等から：
    - 「このウェーブの開始からデバッグプレイ」
    - （余裕があれば）「この時間 t から開始」
  を選択できるようにする。
- リプレイ / シード管理
  - デバッグプレイ時に固定シードを設定し、操作ログを記録・再生してランを再現。
- バリデーション・テスト連携
  - エディタ内「Check」ボタンで JSON バリデーションと軽量ユニットテストを実行し、結果を UI に表示。
- テスト用テンプレ
  - 最小ステージ/スポーンのテンプレをプリセットし、検証環境を即座に生成。
- （Nice to have）シミュレーションモード
  - ユウナ自動操作・描画簡略化・高速進行モード。
  - 指定回数シミュレーションして、勝率や平均生存時間などをエディタに表示。

---

### F-7. Undo / Redo & 保存戦略

**目的:** 編集ミスやクラッシュから安全に復旧できるようにしつつ、快適に操作できるようにする。

#### Undo / Redo

- 画面に ⬅ Undo / ➡ Redo ボタンを配置。
- ショートカット：
  - Undo：`Ctrl + Z`
  - Redo：`Ctrl + Y` または `Ctrl + Shift + Z`
- 戻る単位：
  - タイル塗り：ドラッグ 1 ストローク単位。
  - パラメータ編集：スライダー操作終了時（マウスアップ）で 1 アクション。
  - 拠点移動：ドラッグ開始〜終了で 1 アクション。
- 内部的には、`StageEditorDocument` 等の差分として記録する。

#### 保存・オートセーブ

- 明示保存：
  - 「💾 保存」「💾 別名保存」ボタンを設置。
  - ショートカット：`Ctrl + S`。
  - 押下時に本番用 JSON（例: `assets/stages/level1/...`）を更新。
- オートセーブ：
  - 一定時間ごと（30〜60 秒程度）に `assets/dev/autosave/...` に自動保存。
  - 大きな編集操作後にも自動で autosave に書き出し。
  - エディタ起動時に「前回のオートセーブを復元しますか？」を選択可能にする。
  - autosave / 本保存が衝突した場合は、差分表示付きで復旧選択肢を提示。クラッシュ時は直近バックアップから復旧可能にする。

---

### F-8. 実践的＋α機能

**目的:** 長期的な運用や複数ステージ制作を楽にする「職人向け」機能。

- スナップショット
  - ステージ状態のスロット保存：
    - 例: `level1_easy`, `level1_hard_A`, `level1_hard_B` 等。
  - プルダウンでスナップを選択すると、その状態に復元。
  - スナップ間 diff を表示し、復元前に差分を確認できるようにする。
- タグ / メモ
  - マップタイル / ウェーブ / 拠点などに TODO メモを付与。
  - 「#敵多すぎ」「#ギミック追加検討」等。
  - タグ一覧からジャンプ可能。
  - 担当者 / 優先度 / ステータスを簡易チケット風に付与。
- プリセット / テンプレ
  - ウェーブ構成テンプレ。
  - 敵構成テンプレ。
  - 命名規則テンプレ（例: `stageId_purpose_yyyymmdd`）を用意し、混乱を減らす。
- 難易度ざっくりメーター
  - ステージ/区間ごとの総 HP / DPS / 出現ピークから算出した「危険度バー」表示。
  - 算出根拠（総 HP / DPS / ピーク秒）をグラフで重ねて確認できるようにする。
- ショートカット / カスタム設定
  - よく使う操作のショートカット一覧とカスタマイズを提供。
- テスト結果の簡易ログ
  - 直近デバッグプレイ結果：
    - クリア可否 / プレイ時間 / ちび死亡数 / 拠点ダメージ回数 等。
- ログ / テレメトリ出力
  - デバッグプレイのログやヒートマップ用データは `assets/dev/logs/...` など、  
    本番とは切り離した場所に出力する。
- 作業ログ
  - 誰がいつどのステージを編集したかの開発用ログを dev 領域に保存。

## 6. ステージのメタ情報（将来拡張）

キャンペーン構成や難易度カーブ設計のため、ステージには以下のようなメタ情報を追加できる前提とする（v1 では必須ではない）。

- 想定難易度（★1〜5 など）
- 想定プレイ時間（分）
- 解禁ステージ番号 / 前提ステージ ID
- ステージタグ（例: `short`, `defense-heavy`, `gimmick-heavy` など）

将来的に「ステージ一覧ビュー」や「キャンペーンエディタ」から参照する。

## 7. 非機能要件

### N-1. ビルド分離 / Steam 対策

- エディタ機能は **すべて `EDITOR_BUILD` などのビルドフラグでガード**する。
- Steam 向けリリースビルドではこのフラグを無効にし、  
  エディタ関連コードをコンパイル対象から外すことを前提とする。
- エディタ専用ショートカット・コマンドライン引数（`--editor` など）も同フラグ内で扱う。
- エディタ起動はデバッグビルド + コマンドラインキー + 開発者ユーザー（allowlist）など多段の有効化条件にする。
- リリース時に「エディタ依存のリソースやログ出力先が混入していないか」をリストアップするチェックコマンド/CIを用意する。

### N-2. データ管理・バリデーション

- ディレクトリ構成（例）：
  - `assets/core` … 本番用のベースデータ。
  - `assets/stages` … 実際に遊ばせるステージ群。
  - `assets/dev` … autosave・検証中データ・一時ファイル。
  - `assets/dev/logs` … デバッグプレイ結果・ヒートマップなどのログ。
- autosave / 本番データの衝突検知と安全な復旧フロー（復元前に差分提示、破損時はバックアップから復旧）。
- JSON の署名またはハッシュ記録による整合性チェック。
- ステージ→参照 JSON の依存関係グラフを可視化するビュー/レポート。
- 保存前バリデーション：
  - 参照 ID が実在するか。
  - 数値レンジ（マイナス値やあり得ない値）のチェック。
  - waves の時間がおかしくないか（負値、被り等）。
  - 敵拠点の `rate` が正なのに weights が空 など。
- 壊れた JSON 読込時：
  - クラッシュではなくエラー画面・メッセージで「どのファイル・どのキーか」を提示。

### N-3. パフォーマンス

- 1280×720 / 80×45 マップ＋UI表示で、開発マシン上で快適に動作すること。
- waves やユニット数が増えても、タイムライン編集・スクロールが重くなりすぎないこと。

### N-4. スキーマ変更への耐性

- JSON スキーマにバージョン情報を持たせるか、簡易マイグレーションを用意する。
- ゲーム本体とエディタが **同じスキーマ定義を共有** する形で実装し、片方だけ古くならないようにする。
- JSON スキーマ定義はリポジトリで管理し、バージョンごとの差分マイグレーターをスクリプト化（エディタ側からも呼び出せるように）。
- スナップ / 保存データにスキーマバージョンタグを埋め込み、読み込み時に警告・移行手順を提示。

### N-5. 再現性

- デバッグプレイ起動時のランダムシード管理：
  - 「さっきのランを同条件で再現」を可能な限りサポート。
- エディタからの起動条件（ステージID / シード / 時間ジャンプ位置）をログに残す。

## 9. 運用方針

この要件定義は **v1.0 として運用開始し、実装状況や実際の運用からのフィードバックに応じて随時更新していく。**
開発体制として、ゲーム本体とゲーム内エディタの実装は Codex が担当する（レビュー/マージフローは別途運用）。
